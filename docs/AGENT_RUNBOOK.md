# Agent runbook: EEG → frozen Encoders → Projector → frozen 4B

## Readiness and scope

Read `PIPELINE_STATUS.md` and `NEXT_DAY_PLAN.md` before scheduling hardware. The
old `tools/reproduce.py` is an archived Oracle-only experiment. It is not the new
EEG training pipeline. The new entry point is `python -m elm_pipeline.cli`.

The new entry supports existing Native200 manifests, LMDB or the explicitly
declared HeBin lazy-H5 variant, sharded feature extraction, Projector SFT/alignment,
strict resume within the same workspace, autoregressive Val generation, and
independent report rescoring. Raw adapters for nine logical datasets are included.
Do not infer that every raw-data version or H20 has passed acceptance.
Use `DATASETS.md` for the per-source count/adapter/version checklist. In
particular the CHB adapter preserves a known legacy case split; the full identity
audit rejects CHB01/21 spanning splits until a corrected person policy is supplied.

The new task interface currently covers class reading, six statistic reads, and a
complete report. Historical comparison/count/policy/OPSD code is in `reference/`;
those experiments are not automatically enabled by this interface.

## Environment

Use Linux, Python 3.10 and an assigned full NVIDIA GPU. Do not run model acceptance
or training on the developer Mac. Use two existing compatible environments or
create environments on the training machine with the owner's authorization:

```bash
python3.10 -m venv /work/envs/elm-train
/work/envs/elm-train/bin/pip install torch==2.5.1 --index-url https://download.pytorch.org/whl/cu124
/work/envs/elm-train/bin/pip install -r requirements-train.txt

python3.10 -m venv /work/envs/elm-ar
/work/envs/elm-ar/bin/pip install -r requirements-ar.txt
```

Native200 loading includes `lmdb==2.1.1`; verify the pinned version against
the accepted environment before a production run. No script installs packages,
changes drivers, downloads a model implicitly or changes global CUDA libraries.
The current inference path uses vLLM 0.9.2 V0, with process-local `VLLM_USE_V1=0`.

Keep the two requirements files in separate environments: their Torch,
Transformers and NumPy versions differ. Feature extraction and differentiable
prefix/Projector training use PyTorch and Transformers. The frozen Decoder still
needs an autograd path from its input embeddings to the trainable prefix; do not
replace that training forward with a vLLM inference call. Standalone AR generation
and evaluation use vLLM with `prompt_embeds`. Historical Oracle Student rollouts
inside the training process use Transformers `generate`; this is distinct from
the independent vLLM evaluator. A future large-batch Teacher data generator is
not yet supplied by the current public entry.

Run static tests without a model or GPU:

```bash
python3 -B tools/test_pipeline_static.py
python3 -B tools/test_validate_data.py
python3 -B tools/workbench.py check
python3 -B tools/test_reproduce.py
```


Use the **original Qwen3-4B** ([official model](https://huggingface.co/Qwen/Qwen3-4B)),
not a similarly named 2507, Qwen3.5 or quantized replacement. The archived
`metadata/asset_requirements.json` records the original model identity. For a
ModelScope download, use `Qwen/Qwen3-4B`, then verify those model files. Dataset
hashes are optional; changing the base-model checkpoint is a different experiment.

Example download in a separate asset-download environment. Install that client
only on an authorized machine/environment, not into an already accepted training
runtime. Set its caches to the private workspace. The official
[ModelScope snapshot API](https://github.com/modelscope/modelscope/blob/master/modelscope/hub/snapshot_download.py)
accepts an explicit model ID, revision and local destination:

```bash
HF_HOME=/work/elm-models/cache/hf MODELSCOPE_CACHE=/work/elm-models/cache/ms \
  /work/envs/elm-download/bin/python - <<'PY'
from modelscope import snapshot_download
snapshot_download(model_id="Qwen/Qwen3-4B", revision="master",
                  local_dir="/work/elm-models/Qwen3-4B")
PY

python3 - <<'PY'
from pathlib import Path
import hashlib, json
root = Path('/work/elm-models/Qwen3-4B')
manifest = json.loads(Path('metadata/asset_requirements.json').read_text())
checked = 0
for name, info in manifest['files'].items():
    if info['role'] != 'model':
        continue
    path = root / Path(name).name
    h = hashlib.sha256()
    with path.open('rb') as stream:
        for block in iter(lambda: stream.read(8 * 1024**2), b''):
            h.update(block)
    if h.hexdigest() != info['sha256']:
        raise SystemExit('Base-model identity mismatch: ' + path.name)
    checked += 1
assert checked == 10
print('All 10 original model/tokenizer files verified')
PY
```

`master` is a download locator, not an immutable identity. The ten recorded file
hashes determine acceptance. Preserve a changed download and resolve its version;
do not edit the expected hashes to make it pass. An already downloaded matching
snapshot can be used directly without a network download.

Project assets are intended for
[`wythedee/elm` on ModelScope](https://modelscope.cn/models/wythedee/elm).
The Encoder/Oracle/Projector download bundle is not yet published by this release.
Do not invent a file URL, silently load another checkpoint, or claim a download
succeeded because a repository page exists. Stop the affected model stage until
the manifest and required files are supplied. Never put an access token in the
config, command line, Git history or model card.

To evaluate supplied weights without training first, set `evaluation_checkpoint`
to the provided `.safetensors` file, prepare the declared features, and run
`evaluate`/`report`. This does not need an optimizer or a generated `last.pt`.
Omitting this field evaluates the current run's committed checkpoint instead.

The export tool retains its decompressed historical `.pt` for private audit.
Publish only the explicit safe-tensor files and public metadata in the asset
manifest; never upload the entire conversion directory recursively.

Inference-only Encoder export is about 334 MB, Oracle about 12 MB, Projector about
1 GB. Optimizer/RNG state is a separate larger asset. `initial_projector` means a
weight-only initialization with a new optimizer, not strict continuation.

## Data entry route A: existing Native200 manifests

Each JSONL row declares `id`, `dataset`, `subject`, `label`, `sampling_rate=200`,
`input_shape=[channels,samples]`, canonical channel indices, and its storage
reference. LMDB rows use `lmdb_path` and `lmdb_key`; the payload contains the
trusted preprocessed `sample` array shaped `[channels,patches,200]`.

Legacy HeBin H5 rows instead use `h5_path`, `subject`, `trial_idx`, a 250-Hz
source rate, crop start 125 and length 1000, and lazy 250→200 resampling. Its
result is `[75,800]`. Those 75 legacy grouped positions must not be casually
relabeled as a different set of physical electrodes.

The current loader reproduces source-specific normalization/padding flags,
canonical indices, masks and temporal compression. Do not resize every input to
the same number of channels or append gold labels/statistics to the EEG tensor.

Audit the supplied manifests:

```bash
mkdir -p /work/elm-audits
python3 -B tools/validate_data.py \
  --manifest-root /work/elm-data/manifests \
  --output /work/elm-audits/input01.json
```

The checker reports counts, labels present, dimensions, sample rates, ID conflicts
and known participant aliases. It does not certify every waveform, annotation
mapping or global patient identity. Keep per-person audit output private.
Mumtaz/NEMAR and CHB01/21 must share a participant identity; other TUH patient
mappings still require review. A proper full-data run must resolve overlaps,
including the training provenance of the frozen Encoder.

Historical reference counts are in `metadata/native200_reference_counts.json`.
They are not mandatory byte hashes. Explain differences using source version,
subject inventory, rejected records, window cap and label mapping. Never replace
missing labels or split IDs just to match a count.

## Paths differ between machines

Use relative storage references plus `data_root`, or explicitly map old prefixes:

```json
{
  "data_root": "/work/elm-data",
  "path_map": {
    "/old/data/native200": "/work/elm-data/native200",
    "/old/data/h5/MI/HeBin.h5": "/work/elm-data/h5/HeBin.h5"
  }
}
```

Longest matching prefix wins. The file-level mapping also works for an old
dangling symlink because the mapping is applied before path resolution. No script
edits the original manifest or creates a machine-wide compatibility symlink.
`check` resolves every selected storage path before GPU admission.

If the collaborator supplies `.zst` processed files, recover only what is needed
into a new destination; keep archives and partials. `tools/unpack_processed.py`
requires explicit maximum output size, capacity reserve and absolute deadline.
It uses an existing `zstd`, preserves original paths, verifies decompression exit,
and records the recovered file SHA. Reserve enough space for feature caches and
atomic checkpoint writes too.

## Data entry route B: original recordings

The included raw adapters accept a JSON map of logical dataset names to actual
raw roots. They require entirely new output and manifest directories:

```json
{
  "ADFTD": "/work/elm-data/raw/ADFTD",
  "REEG_PD": "/work/elm-data/raw/REEG_PD",
  "NEMAR_MDD": "/work/elm-data/raw/nm000114",
  "TUAB": "/work/elm-data/raw/TUAB",
  "TUEP": "/work/elm-data/raw/TUEP"
}
```

Example bounded CPU test, with at least three people per class so all splits can
exist. This is an acceptance subset, not full preprocessing:

```bash
CUDA_VISIBLE_DEVICES='' /work/envs/elm-train/bin/python -B \
  -m elm_pipeline.adapters.scalp_native200 \
  --datasets ADFTD --raw-roots /work/elm-config/raw_roots.json \
  --output-root /work/elm-data/native200-smoke \
  --manifest-root /work/elm-data/manifests-smoke \
  --max-subjects 9 --max-windows-per-subject 2
```

For TUEV, TUSZ, HMC_SLEEP and CHB_MIT, use
`elm_pipeline.adapters.event_native200`, the same `--raw-roots` scheme, and its
`--max-windows-per-subject-label` / `--max-subjects-per-group` controls.
Always inspect `protocol.json`, source/subject/window counts, label distributions,
failed records, channel mapping and finite sample checks. An adapter's `complete`
marker must still be checked for recorded failures or missing classes.

The adapters preserve the existing core filter/resampling algorithms: declared
EEG channels, 200 Hz, five-second windows, 0.3–75 Hz and source-specific 50/60 Hz
notch, stored microvolt values, with loader normalization later. ADFTD expects the
matching EEGLAB derivatives and `participants.tsv`; supplying a different raw
export is not automatically equivalent. Event labels and sleep annotations must
match the expected corpus version.

New scalp IDs include a relative-file digest and actual window offset/length, so
changing a cap cannot silently reuse the same ID for a different time window.
`legacy_window_index` is metadata only. Do not confuse source-window metadata
with the loader's crop fields and crop a window twice.

The seven other raw routes (Mumtaz, PhysioNet, HeBin, Shin, Schirrmeister, SEED,
Go/NoGo) are not yet all packaged/accepted by this new interface. Importing their
compatible Native200 manifests is supported. Do not claim a raw-only collaborator
can reproduce them until their matching reader, trial/split builder and acceptance
test are included. The historical 75-group H5 route and a new native-channel
reader are different data versions, even when they share dataset names.

Verified primary starting points, not a promise that every current download has
the identical historical version:

| Data | Primary source | Check before conversion |
|---|---|---|
| PhysioNet MI | [EEGMMIDB 1.0.0](https://physionet.org/content/eegmmidb/1.0.0/) | Run-dependent T1/T2 meaning; movement/imagery run selection |
| ADFTD | [OpenNeuro ds004504](https://openneuro.org/datasets/ds004504) | Matching derivatives, groups and channels |

| HMC | [PhysioNet HMC 1.1](https://physionet.org/content/hmc-sleep-staging/1.1/) | Signal/hypnogram pairing and stage mapping |

For unconfirmed sources, obtain the original acquisition/version details from the
data owner rather than downloading a different dataset with a similar name.
Public metadata links do not authorize redistributing restricted raw data.

## Configure and run the small pipeline

Copy `configs/pipeline_debug.example.json` to a private config directory and
replace all paths and GPU IDs. Use a short project/workspace-local `tmpdir` to
avoid Unix socket path limits. The supplied assets must include the ordered label
schema and six-by-two frozen cuts; do not fit cuts on Val. Without a `thresholds`
file the feature stage fits dataset-weighted thirds from its Train records only.

```bash
mkdir -p /work/elm-runs /work/elm-features /work/elm-tmp
/work/envs/elm-train/bin/python -B -m elm_pipeline.cli \
  --config /work/elm-config/debug01.json check
/work/envs/elm-train/bin/python -B -m elm_pipeline.cli \
  --config /work/elm-config/debug01.json features
/work/envs/elm-train/bin/python -B -m elm_pipeline.cli \
  --config /work/elm-config/debug01.json train --stop-at 30
/work/envs/elm-train/bin/python -B -m elm_pipeline.cli \
  --config /work/elm-config/debug01.json train --stop-at 35
/work/envs/elm-train/bin/python -B -m elm_pipeline.cli \
  --config /work/elm-config/debug01.json evaluate --tag smoke35
CUDA_VISIBLE_DEVICES='' /work/envs/elm-train/bin/python -B -m elm_pipeline.cli \
  --config /work/elm-config/debug01.json report
```

The parent entry chooses the configured training/AR interpreters. Do not invoke
the hidden worker flag manually. GPU admission uses actual FREE memory, three
samples under its lease, and only explicitly allowed devices. Training needs
26 GiB free, AR 24 GiB. Runtime retains 8 GiB physical GPU memory and 20 GiB disk;
other users' PIDs do not by themselves disqualify a card and are never stopped.

Each stage has its own role lock, cache identity and preserved log. The original
pipeline/stage clocks are not reset by rerunning a command. After interruption,
wait for the owned worker/engine to exit and locks to be free. Preserve partial
raw, traces, checkpoints and errors. A trace after the last committed checkpoint
is not a committed optimization step; this prototype refuses ambiguous traces
rather than silently discarding them.

Within an unchanged workspace, the second train command reloads model,
optimizer, full-pass sampler and Python/NumPy/Torch/all-visible-CUDA RNG states.
It checks source/config/data/Oracle identity. Moving paths, changing the target
budget/config or changing the implementation is not a transparent strict resume.

## Inspect artifacts

Feature output contains per-split indexes, tensor shards, per-shard record
metadata, thresholds, rejected-record reasons, `accepted_coverage.json` and
`features_result.json`. A permitted bad-record budget cannot silently remove
every accepted record of a source/split or one of its selected labels.
The raw source files are never rewritten. Data, labels and masks stay in their
declared roles; the Projector receives only both feature banks and masks.

Training output includes `commit.json`, `checkpoints/last.pt`, per-step sample IDs
and task assignments, gradients/frozen-state checks, coverage, and step-specific
training summaries. The current sampler visits a shuffled full pass before
reshuffling. Check unique EEG count, dataset/class coverage and passes, not just
the number of updates.

Evaluation saves `identity.json`, `raw.jsonl` and `summary.json` per explicit tag.
The identity includes full hashes of actual checkpoint/model files, feature
index/shards, Oracle and implementation sources. Reporting verifies those files,
recomputes schema/target correctness from the raw strings, and refuses empty or
partial evaluation folders, missing/duplicate/unknown queries, config changes,
target/question mismatches or a summary inconsistent with the raw strings.
Report class correctness, six per-statistic
scores, report components, whole-report all-correct, format and support counts.
There is no composite task-zero score and no automatic Test generation here.

`report` refuses active role/GPU locks or cache-owned processes. A completed JSON
generation is not a factual success. An `acceptance_result.json` from the internal
server reconstruction test is separate from scientific evaluation, full raw
adapter coverage and H20 validation.

## Before any heavy H20 batch

Use as many **assigned, admitted GPUs** as there are approved ready jobs. Do not
default to serial execution or an arbitrary one/two/four-job cap. After one
implementation smoke/speed check passes, schedule independent cases and seeds
concurrently; refill released slots from the approved queue.

The current trainer is single-GPU. Give each job a distinct physical GPU and a
singleton `gpus` list. A multi-entry list is only an admission candidate list,
not DDP or a global multi-job scheduler. Do not launch every job with the whole
GPU pool and assume they will select different cards. Do not wrap this entry in
`torchrun` without a separate verified distributed implementation. Use separate
configs, output/checkpoint/log/cache directories and locks; model files may be
shared read-only. Serialize stages that write the same job directory.

The larger Oracle proposal is in `NEXT_DAY_PLAN.md`: approximately 100000
candidate training questions, 30000 optimizer steps per case, common evaluations
at 10000/20000/30000, initially three cases by two seeds. These are proposed
targets, not measured throughput, a wall-clock authorization or an implemented
batch launcher. The archived Oracle reproducer remains fixed at 3600 steps.

1. Freeze the dataset version, canonical people, split and label mappings.
2. Check the frozen Encoder's training provenance against that split.
3. Run the assigned H20's short training/save/resume/AR test and measure speed.
4. Use every accepted Train record when claiming a full-data pass. Disable the
   debug cap only in an approved full profile and report actual coverage.
5. Define the exact initial state, two Loss weights, data order, checkpoints,
   primary metric and budget for each ablation. Current proposed core comparison:
   SFT alone versus the same SFT plus Oracle alignment.
6. Give each job one assigned GPU and independent output/cache paths. Do not
   dispatch all proposals in `configs/next_batch.json`; that is an older archive.
7. Return the code commit, config, input audit/counts, model identities, training
   curves/coverage, raw AR outputs, summaries, errors and final verification.

The runbook describes the interface and its boundaries. Update the acceptance
table from actual server artifacts before declaring the release ready.

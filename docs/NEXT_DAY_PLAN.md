# 下一步实验与交付计划

更新：2026-10-31。以下区分已完成的调试、可复现范围和建议开展的研究实验。

## 当前结论

冻结两路 Encoder、原始 Qwen3-4B 和 10200 步 Oracle，只训练 Projector。
Projector 约 2.54 亿参数，输出 80 个 2560 维 tokens：32 个类别位置和六组各
8 个统计位置。Encoder 仍保留 200→50 的维度压缩、每通道两个时间位置和有效通道掩码。

当前监督只有答案 SFT 和 token 对齐：

```text
L = answer_token_mean_CE
    + mean_tokens(MSE(pred, target) / mean(target²))
    + 0.1 * mean_tokens(1 - cosine(pred, target))
```

Oracle 目标停止梯度。EEG 学生的输入不含正确类别、统计档位或参考答案文字。
GT 用来构造监督和计算 Loss。两路 Encoder、4B、Oracle 均不更新。

### 最近报告训练

训练数据为 2326 条 EEG，验证为同一批 128 条 EEG，分别询问类别、六个统计值和
完整报告，共 1024 个问题。训练批次为 50% 类别、25% 统计单问、25% 完整报告。

| 总步数 | 类别单问 | 六统计单问 | 报告内类别 | 报告内六统计 | 完整报告七项全对 | 格式有效 |
|---:|---:|---:|---:|---:|---:|---:|
| 3600 | 64/128 | 540/768 | 7/128 | 271/768 | 0/128 | 100% |
| 5100 | 67/128 | 514/768 | 63/128 | 450/768 | 6/128 | 100% |
| 6600 | 66/128 | 534/768 | 61/128 | 541/768 | 8/128 | 100% |

报告监督已使“报告里的字段”接近单问表现。主要问题转为各字段的读取准确率，
而不是 JSON 无法生成。整份报告要求七项同时正确，不能用格式有效率替代全对率。
这些都是小规模 Val 调试结果，不是完整 Test、临床结论或严格泛化结论。

## 夜间已完成的软件验收

通过 `elm_pipeline` 的新路径入口，实际完成：

1. 路径从 JSON 配置读取，旧绝对路径可以显式映射；不要求新机器复刻原目录。
2. Native200 LMDB / 声明过的 lazy H5 → 两路冻结 Encoder → 特征分片。
3. 选中记录的新特征与旧缓存逐 ID 比较，mask/bin 精确一致；数值与 BF16 特征误差单列。
4. 服务器 30 步训练、保存、独立进程恢复到 35 步，检查全参数/80 槽梯度、冻结状态、优化器和 RNG。
5. 使用真实生成入口出答案，再独立解析原始输出、生成逐任务报告。
6. ADFTD 原始文件 9 人、18 窗口 → Native200，Train/Val/Test 各 6 条，零错误；
   再接两路 Encoder、现有 35 步权重、真实生成和报告，未增加优化步。

16 来源共重建 64 条特征，mask/bin 与旧缓存完全一致，特征余弦均大于 0.999。
32 条 Train 完成 30 步并在独立进程恢复到 35 步，全部参数和 80 个位置有梯度，
优化器和随机状态恢复通过，训练 Torch 峰值 13.24 GiB。主短测生成 512 个回答，
ADFTD 原始数据接续生成 96 个回答，均已独立解析和输出报告。

这 35 步是新初始化 Projector 的软件短测，不能拿其准确率与旧 6600 步模型比较。
另已用安全导出的 6600 步权重在 NORVE 独立加载，完成 32 条 EEG 和 6 条原始
ADFTD 窗口的生成及报告，共 608 个 Projector/Oracle 回答，没有新增训练步。
推理时使用的权重、模型、特征和代码均核对 SHA，完整题目覆盖和原始答案重算通过。

软件短测只证明执行链路，不能当作模型质量提升。当前原始数据适配器并非全部已验证；
每个入口需要在验收表中分别标记，不能用已经存在的 feature cache 代替原始数据验收。

已发现 HeBin 的历史 H5 路径指向压缩前的文件。处理方式是从现有归档恢复到新的
项目目录，已完整恢复并验证 47.76 GB 的 H5；再用 `path_map` 明确映射。
未改旧 symlink、未删除归档。这个实际问题也已纳入路径检查和复现指南。

## 先修正数据身份，再谈正式泛化

- MUMTAZ 与 NEMAR_MDD 是同一来源人群的两种表示，原来的独立切分有跨名称重叠。
- CHB 的 chb01 与 chb21 是同一人不同时间的记录，不能按两个目录名当成两个人。
  来源：[PhysioNet CHB-MIT Methods](https://physionet.org/content/chbmit/1.0.0/)。
- TUH 不同子库及版本之间的患者 ID 对应关系还需要核对。
- 已有 Encoder 也按历史数据训练过。只调整 Projector 的切分，不能证明 Encoder
  从未见过这些受试者。正式协议要么重新按正确 Train 训练相关 Encoder，要么明确
  标为使用历史 Encoder 的迁移诊断。

建议将“历史流程复现”和“修正身份后的正式研究”作为两个数据版本，保留所有旧结果。
同一数据版本内才比较 Loss 和组件。

## 全量训练的含义

历史 Native200 清单共 447545 条窗口：Train 313626、Val 61474、Test 72445。
这包括同源逻辑名称和部分按受试者/标签限制窗口数的预处理；它不是 447545 个
独立人，也不是对所有原始连续信号完全不截取的版本。去重后要重新给出数量。

后续不能把 2326 条调试子集称作全量。全量阶段应记录每个数据集、类别、受试者和
窗口的实际覆盖量，并保存采样顺序。新入口提供打乱后不放回的完整遍历，最后一批
可跨到下一遍；一个 EEG 被访问一次也不代表它已经接受所有题型的监督。

原清单按 batch 8 完整访问一次约需 39204 个优化步。旧的 6000 步只对应 48000 次
样本访问，不能保证覆盖这份 Train 清单。正式预算应先通过实际速度测试决定，
不能照搬调试阶段的步数。

## 建议先跑的研究实验

以下是待确认的计划，不是已经启动的运行。

1. **全量覆盖 pilot。** 修正并冻结数据版本后，覆盖全部 Train EEG，先检查各来源
   的类别/统计读取是否都存在信号，记录吞吐、显存、数据覆盖和保存恢复开销。
2. **两组核心对照。** A 只用 SFT；B 用同样 SFT 加 Oracle token 对齐。固定同一
   初始化、数据顺序、80 tokens、训练访问量和评测。首先回答“对齐到底有没有用”。
3. **再做组件消融。** 在 B 稳定后，比较类别/统计两路特征、压缩或 Projector 组件。
   每次明确改变哪一项。暂不把 auxiliary head、diversity loss、OPSD、更多 tokens
   和更多问题难度同时叠加。
4. **最后检查任务泛化。** 保留未见受试者、未见题面和组合任务等分组；文本、Oracle、
   EEG 三种输入分别评测，给出文本正确子集的支持数和 EEG 保留比例。

已有 6600 步运行不延长、不重新打开。新的长运行另存目录，并在数据和预算确定后开始。

## H20 交付方式

优先一张卡跑一个明确对照，多个对照使用独立目录、缓存和 GPU 分配。先在一张 H20
做短测及速度标定，再扩大并行。现有 A100 上的成功不能写成 H20 已验收。

GitHub 提供代码、配置模板、环境、数据适配说明、命令、验收方式和失败处理。模型
资产单独提供：冻结 Encoder 约 334 MB、Oracle 约 12 MB、Projector 约 1 GB，
4B 从官方模型仓库获取。安全权重只包含推理所需 state，不含 optimizer；需要严格
续训时另行提供训练状态，不能把“只加载权重”描述为严格连续训练。

原始 EEG、缓存特征、个人逐样本输出和 Token 不进入 public Git。ModelScope 文件
尚未发布时，指南必须标明待提供，不能给出不存在的下载文件或自动换模型。
